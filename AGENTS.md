# Repository Guidelines

## Project Structure & Module Organization

Python backend code lives in `src/agentic_ops/`; tests are in `tests/`. The React/TypeScript/Vite UI is under `web/`. Specs, design notes, and the roadmap are under `docs/`. Fictional runbook Markdown/PDF assets live under `data/runbooks/`; editable service guides, historical postmortems, and deployment guidance live under `data/knowledge_base/`. Regenerate runbook PDFs with `uv run python scripts/build_runbooks.py`. The seeded search archive is generated by `scripts/generate_search_corpus.py`; its 20,000 records and index files belong under ignored `.data/`. A sample and manifest are tracked under `data/`.

## Build, Test, and Development Commands

From the repository root, sync dependencies with `uv sync --locked --extra rag-gpu`. Check GPU/model availability with `uv run python scripts/check_gpu.py`; generate and index the local archive with `uv run python scripts/generate_search_corpus.py --seed 42` and `uv run python scripts/build_search_index.py`. The first model use downloads the embedding and reranking models from Hugging Face. Evaluate retrieval with `uv run python scripts/evaluate_search.py`. Then start the API with `uv run python -m uvicorn agentic_ops.api:app --app-dir src --host 127.0.0.1 --port 8000`. In a second terminal, run `Set-Location web`, `npm ci` (first install), then `npm run dev -- --host 127.0.0.1`; open `http://127.0.0.1:5173/`. Keep both servers running; Vite proxies API requests to port 8000. Set `UV_CACHE_DIR` to a writable user cache directory if uv's default cache path is unusable. The backend reads only `OPENAI_API_KEY` from the ignored root `.env` when an investigation is requested; use `AGENT_MODE=mock` only for an offline deterministic demo.

Run one API instance without automatic reload. Stop it with Ctrl+C before restarting after backend edits. If its terminal is unavailable, stop the API listener with:

```powershell
Get-NetTCPConnection -LocalPort 8000 -State Listen -ErrorAction SilentlyContinue |
    Select-Object -ExpandProperty OwningProcess -Unique |
    ForEach-Object { Stop-Process -Id $_ -Force }
```

For the event-driven prototype, choose Automatic or Manual investigation mode when starting each replay; Automatic is the default. Automatic mode investigates episode openings, relevant service or issue changes, and a final episode-ending update when it adds a newer evidence cutoff. The worker uses the OpenAI investigator by default and requires `OPENAI_API_KEY`; set `AGENT_MODE=mock` for offline reports. Automatic live investigations use API credits. The incident queue and detector checkpoints are persisted; replay workers do not resume after an API process restart.

Use port `5173` for the UI. Verify the selected port is free before restarting; avoid terminating unrelated project processes. Saved investigation URLs reopen reports without another OpenAI call.

## Coding Style & Naming Conventions

For Python, use four spaces, type hints on public interfaces, `snake_case` functions/modules, and `PascalCase` types. Keep simulation truth separate from observable events, statistical functions pure, and LLM/provider code outside the detector core. Retrieval may inspect ticket text and evidence, but all time-varying evidence searches must enforce the selected investigation cutoff. Use TypeScript with React components in `PascalCase` and local variables in `camelCase`.

## Testing Guidelines

Place Python tests under `tests/` as `test_*.py`. Cover seeded simulation, count-to-ticket reconciliation, independent text randomness, statistical boundaries, truth isolation, cutoff enforcement, PDF page and Markdown section citations, retrieval ranking/cache behavior, and API behavior. Use deterministic embedding/reranking fakes in unit tests; never make paid API calls or download models from the test suite. Run the focused tests while editing and the full suite before handoff. Build the frontend with `npm run build` from `web/`.

## Commit & Pull Request Guidelines

History uses concise imperative subjects, sometimes with a `feat:` prefix. Follow that style (for example, `Add rate detector boundary tests`). Pull requests should explain the behavior changed, checks run, and impacts on generated data or detector outputs. Include linked issues or screenshots when relevant.

## Data and Security

Use synthetic or public data only. Never add employer/client code, confidential schemas, credentials, or private incident records. Keep generated artifacts reproducible and identify the seed and command used when sharing results.
